What this is

Router-Maestro is a local or self-hosted proxy that lets OpenAI-, Anthropic- and Gemini-compatible clients use models from GitHub Copilot, OpenAI, Anthropic and custom endpoints, with priority-based selection and automatic fallback. This page is that proxy drawn as a town, with one request driving through it.

The avenue is everything the proxy does before it will name a model: the Gatehouse checks the server key, the Customs House rewrites the client's dialect into one canonical request, the Weighbridge counts tokens, the Naming Office turns an alias into a concrete provider/model, the Inspection Shed ranks candidates by capability, and the Dispatch Tower freezes the plan. The ring road east of the tower is one attempt: mint a credential, re-encode the body, call the provider. A retryable failure sends the van round it again with the next candidate — the loop in the road is the loop in the code. The response comes home on its own road, through the Guard Tunnel and the Wire Room. A request refused at a checkpoint never gets that far: it reverses down the avenue it came up.

The van carries the request, it does not represent it. The gauge on its flank is the prompt measured against the chosen model's usable budget. The crates are the tokens on the wire. The three roof lamps are the features the request uses — tools, vision, reasoning — which is exactly what the Inspection Shed checks it against.

How much of it is real

Genuinely computed, live, in your browser, in js/model.js, ported function for function from the repository: the token accounting (three tokens of overhead per message, one for a name, sixteen flat for having tools plus eight per tool and a 1.1× safety margin on every schema, three for reply priming — the constants in utils/token_config.py); the image tile cost from utils/tokens.py; the context budget formula from utils/context_window.py, including the rule that caps effective output at 15% of the prompt budget; alias normalisation, date-suffix stripping, family selection and the newest-version tiebreak from utils/model_match.py and utils/model_sort.py, with its real thresholds — 80 to be considered, 85 to be confident, and two families within one point of each other is ambiguous rather than a guess; three-valued capability support and the supported-then-unknown ranking from routing/capabilities.py; the route plan, the fallback strategies and the frozen retry limit from routing/router.py; the upstream status classification (429, 500, 502, 503, 504, 529 retryable; everything else not) and the fallback decision from providers/base.py and routing/attempts.py; the reasoning-tier ladder and its highest-at-or-below-you clamp from utils/reasoning.py; and the bounded prefix matchers of the leak guard from pipeline/leak_guard.py, which really do scan the streamed text delta by delta.

Scaled down: a nine-model catalogue instead of a live one of hundreds; a conversation of a few turns instead of a few hundred; a response of about twenty deltas. Text is costed at three characters per token — the repository's own estimate_tokens_from_char_count — because there is no tiktoken BPE table in a browser, so every token figure here is an estimate of an estimate. The file context you dial in is costed by character count rather than by materialising half a megabyte of source. The blocks on the weighbridge are one per 2,000 tokens; the crates on the van are one per 4,000 prompt tokens outbound and one per 25 output tokens on the way home.

Sourced: the GitHub Copilot prompt and context-window limits are the catalogue figures recorded in docs/copilot-context-limits.md. That document also notes that the catalogue number is a soft recommendation several models exceed in practice.

Assumed / modelled: every millisecond. Nothing here touches a network. The station costs are order-of-magnitude figures chosen so the shape of the bill is right — the upstream call dwarfs everything the proxy does, and the proxy's own time is dominated by tokenising the prompt. An oversized prompt is modelled as a 400 from the upstream, which is what makes it stop rather than fall through; a real upstream may accept more than its catalogue claims. The capability flags, the max-output figures and the non-Copilot limits are plausible, not fetched.

Deliberately faked: the assistant's reply text is canned — nothing here ran a model — and the upstream failures are dialled in by you rather than observed. What is real is the scanner that reads that text and the policy that reads those statuses. Treat the reply as scenery; treat the routing as the lesson.

Pacing

The first time the van reaches a station it stops for long enough to read that station's write-up — between 9 and 26 seconds, depending on how much there is to say — and a progress bar under the panel text shows how much of the stop is left. Once every district has been explained the town runs at a watchable pace instead of a readable one. Space holds any stop indefinitely, S steps one station at a time, and the Speed slider scales everything, reading stops included. Reset (⟲) replays the slow tour; Run keeps what you have already read.

Things worth trying

  • Set Model asked for to claude: four families score within a point of each other, so it is a 400 rather than a guess, and the van turns back at the Naming Office.
  • Set it to haiku with reasoning above none: the only model serving that id has said it cannot reason, so there is no compatible route at all.
  • Push File context past 500 KB: the prompt outgrows the model's budget, the upstream returns 400, and — because a 400 is not retryable — the router stops instead of pushing the same oversized body at the next provider.
  • Set Upstream health to "first choice 401" and watch the same road produce the opposite decision from a 429.
  • Set Fallback to none, or Max retries to 0, and watch the plan board lose its spare bars before the request ever leaves the tower.
  • Set Response contains to a control envelope: the Guard Tunnel cuts the stream part-way and the client is told to retry the turn.

Controls
